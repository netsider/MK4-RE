==========================================================================================
A. FILE FORMATS
==========================================================================================
A1. ECM video codec
    Done: fully decoded. Header 0xE18 bytes ("ECM" 0x02, u32 frames, 900 x u32 chunk sizes; 0xE18 + sum = file size
    for all four files, M_INTRO included - the "different header" was a misreading). Chunk = 1 s = 15 frames:
    "SEC" 0, 0x2B14 bytes IMA ADPCM sound (22050 Hz mono, state carried over; VA 0x4AC190), then an EDL block
    (Eurocom LZ + Huffman, VA 0x4B07E0) holding "MPC" 0x02 video: 5-5-5 palette, 80 x 60 codes of 4x4 blocks per
    320x240 frame, codebook at +0x23484, code >= 65000 = solid colour. Guide section 5.
    Evidence: tools\ecm_tool.py's EDL output is byte-identical to the EXE's decompressor and its frames to the EXE's
    frame routine VA 0x4BDD50 (frames 1-14 of M_MIDWAY and M_INTRO chunks 0-1, run in an emulator). Content seen:
    Midway logo (152 frames), Eurocom logo (203), trailer (331), Raiden intro (1000).
    Open: the game's random "soften" pass on solid blocks is not reproduced (cosmetic); sound checked as smooth
    waveforms only, not by ear (LIKELY).
    Status: PROVEN. DONE.
A2. GEO block types 0x100 and 0x2
    Done: the draw dispatch VA 0x4BA01D reads byte 0 of the type word as flags; byte 1 is never read by the draw or
    prep code (VA 0x4BB840). So 0x100 draws exactly like type 0 (normal lit renderer VA 0x4BAA60); 0x2 = byte 0 bit 1
    -> VA 0x4BAF60, per-vertex shade from depth (VA 0x4B2990), used only by buyin_ge. Also 0x40 -> VA 0x4BAD10
    (no lighting call; one part per arena) and bit 0 + object flag 0x80000 -> VA 0x4BA630 (optional path).
    0x100 parts: shared_g 64, share2_g 22, lair/prison/skull/tomb/wind; mostly 2-triangle quads or repeated copies.
    Status: PROVEN (code paths) / LIKELY (0x2 = depth-shaded look, 0x40 = unlit, byte 1 = editor/group flag) /
    GUESS (0x100 parts = effect frames picked by object code).
    Get it (rest): watch the buy-in screen and an arena with 0x100 parts; find who picks 0x100 part numbers.
A3. GEO "2D set" table (types 128..640, count 0)
    Done: these are 2D SPRITE records, byte 0 bit 0x80 (draw VA 0x4BB180; pair path VA 0x4BA4D1). Layout, 16 bytes:
    +0 flags (0x80 sprite, 0x01 = draw the next record too), +1 blend & 3 (table VA 0x4F41C0: 0 opaque, 1/2 additive,
    3 = 50/50 translucent), +2 GEO-local page, +3 sequential id (unread), +4/+6 s16 screen w/h, +8/+0xA s16 screen
    x/y, +0xC/+0xD u8 u/v, +0xE/+0xF u8 texel w/h (screen size may differ: stretched). The "count 0" was bytes 2-3
    (page 0, id 0) read as a u16. Guide section 3.
    Status: PROVEN (layout and draw code) / LIKELY (visual look of the blend modes). Which screen uses which file:
    LIKELY from the file names; the fatality-effect use is still a GUESS.
A4. GEO block type 0x4 (Midway logo, MK title logo, attract medallion)
    Done: 0x4 = byte 0 bit 2, which no renderer tests -> the normal lit renderer; same mesh layout as type 1.
    tools\export_pc_geo.py now takes every 3D record when a file has no type-1 parts (logos, buyin_ge, arenas),
    skips 2D sprite records instead of stopping, and stacks several texture pages into one atlas. Exports: midway_g
    2 parts / 2336 triangles (3D "MIDWAY" logo), MKlogo_g 19 parts / 2033 (UVs on colour swatches: flat-coloured
    mesh), attract_ 1 part / 1692 on 2 pages (dragon medallion). Fighter output is byte-identical to before.
    Status: PROVEN (layout, export). Not yet compared side by side with the in-game title screens.
A5. Sprite cut-out rectangles
    Done (rectangles only): the 2D sprite records of A3 ARE the rectangles: page, u, v, tw, th, plus the on-screen
    size and offset. Triangle UVs on 3D parts give the rest.
    Not done (on purpose, for now): no sprites have been cut and no cutter tool is included.
    Status: PROVEN (layout). Cutting: open.
A6. Texture transparency key
    Done: texel value 0x0000 (pure black) is transparent. The game renders in software (DDRAW + DSOUND, no Direct3D);
    its textured span loops skip a texel equal to 0, e.g. VA 0x4BF2B1 "test ax,ax; je skip" (14 loops in
    VA 0x4BEC00-0x4C2400). Bit 15 can't be a key: it is the RLE run flag. Blend modes come from the polygon mode
    bits (A3).
    Status: PROVEN. DONE.
A7. GEO UV row byte 0
    Done: byte 0 = GEO-local texture page. VA 0x4BB943 reads it (movsx) and maps it through the loaded file's page
    table (VA 0x4BC810 writes {slot, slot} at tex_off + 8 + 4*page) into the polygon's page bits. Check: byte 0 <
    page count in all 107,176 rows of all GEOs. Byte 1 (previously called the page) is never read by the game:
    values 0-144 in runs, not the strip index.
    Status: PROVEN (byte 0) / LIKELY (byte 1 = editor-only group/material id).
A8. ESF flag 0x80 (13 files)
    Done: loop flag. The ESF loader VA 0x4B0600 returns bit 31 of the header word; VA 0x4C225A stores it as bit 0
    of the sound slot's flag byte (VA 0xF8D9A6 + 28 * n); the play routine passes that bit as the flags argument of
    IDirectSoundBuffer::Play (VA 0x4C2783 -> call [vtbl+0x30]) = DSBPLAY_LOOPING; the stop routines VA 0x4C2943 /
    0x4C29DD stop only these sounds. Also from the same loader: bit 29 = 16-bit output (ADPCM), bit 30 = 22050 Hz.
    The 13: pcmk0101, 0102 (8-bit 11 kHz); pcmk2003, 2007, 2011, 2015, 2023, 2031, 2035, 2039 (= sound codes 3, 7, ...
    39 = each arena music code + 2); pcmk2070, 2071, 2081 (12-16 s).
    Status: PROVEN (loop). What they are: LIKELY arena ambience loops (not listened to / not checked live).
A9. MENU.TGA use
    Done: loaded once at start-up: init VA 0x4B1A70 -> VA 0x4B5580 opens "c:\source\mk4\win\menu.tga" (VA 0x4F40D0),
    skips the 18-byte TGA header, reads 256 rows bottom-up into the staging buffer and copies it to texture slot 15
    (VA 0x4BE440(15, 0, 0, 256, 256)); GEO pages only use slots 0-14. Content: ASCII font, colour swatches, blue
    dragon medallion.
    Status: PROVEN (load, slot 15) / LIKELY (shown as the font/background of the PC set-up and key-config menus).
    Get it (rest): find the code that draws from slot 15.

D1. Script opcodes (handler table 0x4E6970, 128 entries)
    Done: every handler disassembled; tools\script_decoder_v3.py "ops" lists name, operand words, effect and tag for
    all 128. PROVEN now: 03 (LIKELY), 04 n animate n ticks / stop at clip end, 4A n animate until frame <= n,
    34 = the plain sleep (05 = wait while animating, LIKELY), 5A push back, 5C gravity, 5D nudge, 65 velocity to the

    Status: partial-LIKELY - still not traced: 01, 02, 05, 08, 0D, 14, 17, 1C, 1D, 24, 28, 2E, 40, 44, 4D, 4F, 56, 59
    (internals), 60, 62, 64, 69, 6A, 6D, 6F, 71, 72, 76, 7C.

D2. Byte-argument calls: sound / effect / damage
    Done (PROVEN): 20/25/26/27 = sound tables 0x4ED998 / 0x4EDD18 / 0x4EDAE0 / 0x4EDA00; 2B = per-fighter voice
    (random lists); 2C = per-fighter line; 73/74/75 fixed sounds; 2A = effect process (LIKELY); damage = strike
    +0x14 and op 63. Sound code -> file: code > 100 -> pcmk(code/5), <= 100 -> pcmk(2000+code), music codes -> CD

    Open: 4 table codes point to files that do not exist (pcmk0888, 1037, 1204, 1207 - GUESS: silent on PC);
    op 20 with index > 0x32 (e.g. the sweep's 0xAF) plays nothing on PC.

D3. Native-code chains (Square Wave, Bicycle Kick)
    Done: control flow traced (guide section 8A). Square Wave: clip 310, rise at -0.15/tick to height -2.5, clip 101 at

    Bicycle: per-tick hit check; on hit both fighters move together, velocity x 0.6, 32-tick end phase, clip 72, the

    Status: PROVEN (flow); names of helper routines LIKELY.
D4. Condition table 0x4E7EA8
    Done: every used entry read (guide section 8B step 3; script_decoder_v3.py "conds"): cool-down timers, own/opponent

    Open: 0C (held-button list unclear, GUESS); what each timer event T(n) is.
    Status: PROVEN (code) / LIKELY (field names)
D5. Command tables and the Player 2 tables
    Done: input words 0x4D30A4 / 0x4D30A8 and their press/release lists traced. 0x5405F8 = LK RELEASE (PROVEN; not
    "held"); 0x540688 = RUN bit (PROVEN, name LIKELY); 0x540448 = joystick up (LIKELY). P2 tables 0x5406D0-0x540880
    and 0x540640 hold exactly the P1 contents (PROVEN statically, 144/144 entries).
    Status: PROVEN except the "up" name (LIKELY). Not re-checked live.
D6. Action-table sizes
    Done: misc 0x44 slots, aux 0x14, special 0x23, projectile 0x1B, bit-5 table 0x50 (from where the next data starts;

    Status: LIKELY (sizes) / PROVEN (dispatcher)
D7. Strike record fields
    Done: +0x10 byte 0 = reaction (standing), byte 1 = reaction if the victim is airborne, byte 2 = reaction when

    Open: hit box +0x00..+0x0C (LIKELY x, y, w, h).
